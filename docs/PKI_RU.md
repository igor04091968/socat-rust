# Встроенный генератор ключей, CSR и сертификатов

Начиная с v0.1.13 команды `socat-rust pki` работают внутри бинарника,
через статически связанную криптобиблиотеку. Внешняя программа `openssl`
для генерации не нужна. Конфиг relay не читается, сокеты не открываются,
работающие relay и системное хранилище доверия не меняются.

Нужен бинарник `socat-rust-linux-amd64-tls-static` или
`socat-rust-linux-amd64-tls-gost-static`. ГОСТ доступен только во втором.
В TCP-only и `legacy-kernel` генератор недоступен.

## Ключ и самоподписанный сертификат для обычного TLS

В новом закрытом каталоге выполните:

```bash
mkdir -m 0700 pki-demo
cd pki-demo
socat-rust pki keygen --algorithm rsa3072 --out server.key
socat-rust pki self-signed --key server.key --out server.pem \
  --cn relay.example.org --dns relay.example.org --ip 192.0.2.10 \
  --usage server --days 365
```

Для ECDSA замените `rsa3072` на `ecdsa-p256`. Ключ создаётся в незашифрованном
PKCS#8 PEM; сертификат — в X.509 PEM. Файлы принадлежат пользователю запуска
и создаются с правами `0600` (umask может дополнительно сузить их).

Самоподписанный сертификат не получает доверие автоматически. Для закрытой
пары relay можно явно установить его на другой стороне в `ca_file`, сохранив
проверку `server_name`. Для сертификата от УЦ используйте CSR, как ниже.

## Запрос сертификата для своего УЦ

Используйте уже созданный ключ:

```bash
socat-rust pki csr --key server.key --out server.csr \
  --cn relay.example.org --dns relay.example.org --ip 192.0.2.10 \
  --usage server
```

В УЦ передаётся только `server.csr`. Закрытый ключ остаётся у владельца.
CSR имеет формат PKCS#10 PEM и содержит запрошенные SAN, Key Usage,
Extended Key Usage и `CA:FALSE`. Окончательные поля сертификата определяет УЦ.
Полученную цепочку укажите в `certificate`, исходный ключ — в `private_key`.

## ГОСТ-2012

В бинарнике с `tls-gost`:

```bash
socat-rust pki keygen --algorithm gost2012-256 --out gost-server.key
socat-rust pki self-signed --key gost-server.key --out gost-server.pem \
  --cn gost.example.org --dns gost.example.org --ip 192.0.2.20 \
  --usage server --days 365
socat-rust pki csr --key gost-server.key --out gost-server.csr \
  --cn gost.example.org --dns gost.example.org --usage server
```

Также доступен `gost2012-512`. Генерация использует набор параметров `A`
для выбранной размерности и подпись ГОСТ Р 34.11-2012 соответствующей длины.
Параметрический набор через CLI пока не выбирается. Алгоритм подписи CSR
и сертификата определяется по существующему ключу; повторно указывать его
не требуется. Обычные RSA/ECDSA-ключи подписываются с SHA-256.

Для ГОСТ TLS relay проверен с ключом `gost2012-256`.
Возможность создать 512-битный ключ и подпись не означает совместимость
512-битного сертификата с имеющимися TLS-наборами или внешним сервисом.
Перед использованием ГОСТ-сертификата в рабочем контуре согласуйте профиль
ключа, сертификата и TLS с другой стороной. Генератор не является
сертифицированным СКЗИ и не создаёт контейнеры CryptoPro CSP или токены.

## Параметры

| Команда | Параметры |
|---|---|
| `pki keygen` | `--out` обязателен; `--algorithm` по умолчанию `rsa3072` |
| `pki csr` | `--key`, `--out`, `--cn`; SAN и назначение — ниже |
| `pki self-signed` | Те же параметры и `--days` от 1 до 3650, по умолчанию 365 |

Алгоритмы: `rsa3072`, `ecdsa-p256`, `gost2012-256`, `gost2012-512`.

| Параметр идентичности | Значение |
|---|---|
| `--cn` | Common Name, 1–64 байта UTF-8, без управляющих символов |
| `--dns` | DNS SAN; повторяется для нескольких имён; ASCII/punycode, допустим `*.example.org` |
| `--ip` | IPv4/IPv6 SAN; повторяется для нескольких адресов |
| `--usage server` | `serverAuth`, значение по умолчанию |
| `--usage client` | `clientAuth`; SAN можно не задавать |
| `--usage both` | `serverAuth` и `clientAuth` |

Для `server`/`both` нужен хотя бы один `--dns` или `--ip`.
CN не заменяет SAN. Всего допускается до 100 SAN. IP задавайте через `--ip`.
Самоподписанный сертификат имеет случайный положительный серийный номер,
срок действия от текущего времени и `CA:FALSE`: выпуск сертификатов УЦ
и подписание чужих CSR этими командами не реализованы.

## Установка материалов в профиль relay

Установите ключ и сертификат отдельно, назначив владельцем UID/GID профиля:

```bash
sudo install -d -m 0755 /etc/socat-rust/pki
sudo install -d -o 2450100 -g 2450100 -m 0700 /etc/socat-rust/pki/demo
sudo install -o 2450100 -g 2450100 -m 0600 server.key /etc/socat-rust/pki/demo/server.key
sudo install -o 2450100 -g 2450100 -m 0600 server.pem /etc/socat-rust/pki/demo/server.pem
```

`2450100` замените на UID своего профиля. В конфиге для входящего TLS:

```toml
[relay.inbound_tls]
mode = "tls"
certificate = "/etc/socat-rust/pki/demo/server.pem"
private_key = "/etc/socat-rust/pki/demo/server.key"
```

Таблица добавляется к полному `[[relay]]` из [инструкции запуска](RUNNING_RU.md).
Для ГОСТ используйте ГОСТ-материалы и `mode = "gost"`.
Проверьте `config-check`, затем перезапустите только нужный профиль.

## Повторный запуск и ошибки

Существующие файлы и симлинки не перезаписываются. Ключ, сертификат и CSR
создаются отдельными командами: ошибка сертификата не удаляет готовый ключ.
При ошибке записи частичный выходной файл сохраняется, команда завершается
с ошибкой; проверьте этот файл перед явным удалением или выберите новое имя.
Родительский каталог должен уже существовать и быть доступен пользователю.

Зашифрованный входной ключ отклоняется без запроса пароля. Поддержки
парольного шифрования ключей, продления, автоматической ротации, ACME,
CRL/OCSP и установки доверия в генераторе нет. Для использования TLS и
ГОСТ смотрите [TLS_GOST.md](TLS_GOST.md).

Справка: `socat-rust pki --help` и `socat-rust pki self-signed --help`.
